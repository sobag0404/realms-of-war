    40→    40→## 1. Краткий вердикт
    41→    41→
    42→    42→`Realms of War` — амбициозный alpha-прототип fantasy 4X/TBS-игры на **Next.js + TypeScript + React Three Fiber + Zustand + Prisma/SQLite**.
    43→    43→
    44→    44→Проект выглядит значительно серьёзнее обычного учебного CRUD: есть игровой engine, hex-математика, ECS-подход, command pattern, EventBus, mapgen, AI, workers, 3D-рендеринг, HUD, save/load, GDD и project context.
    45→    45→
    46→    46→Но по engineering discipline проект пока не production-ready. Основные блокеры:
    47→    47→
    48→    48→- публичные save/load/delete API без авторизации и ownership;
    49→    49→- опасный Caddy reverse proxy через query-параметр `XTransformPort`;
    50→    50→- `next.config.ts` игнорирует TypeScript build errors;
    51→    51→- ESLint фактически обезврежен;
    52→    52→- реальных тестов нет;
    53→    53→- save/load в UI/API обходит engine-level save-модуль;
    54→    54→- детерминизм заявлен в архитектуре, но нарушен через `Math.random()` и `Date.now()` в engine/rules/workers;
    55→    55→- есть placeholders в пользовательских действиях;
    56→    56→- нет полноценного root `README.md`, `.env.example`, CI/CD и production-инструкции.
    57→    57→
    58→    58→**Текущий уровень:** сильный WIP/alpha-прототип, ближе к `junior+ / middle-` по зрелости реализации. Архитектурная задумка местами тянет на `middle/middle+`, но безопасность, тесты, build discipline и deploy-подход ниже production-уровня.

   352→   352→### 5.6. Caddyfile содержит SSRF/open proxy риск
   353→   353→
   354→   354→Файл: `Caddyfile`
   355→   355→
   356→   356→```caddy
   357→   357→@transform_port_query {
   358→   358→  query XTransformPort=*
   359→   359→}
   360→   360→
   361→   361→handle @transform_port_query {
   362→   362→  reverse_proxy localhost:{query.XTransformPort} {
   363→   363→    header_up Host {host}
   364→   364→    header_up X-Forwarded-For {remote_host}
   365→   365→    header_up X-Forwarded-Proto {scheme}
   366→   366→    header_up X-Real-IP {remote_host}
   367→   367→  }
   368→   368→}
   369→   369→```
   370→   370→
   371→   371→Проблема: пользовательский query-параметр управляет локальным портом reverse proxy. Это потенциальный SSRF/open local proxy.
   372→   372→
   373→   373→### 5.7. Детерминизм нарушен
   374→   374→
   375→   375→Архитектурная цель из `PROJECT_CONTEXT.md`:
   376→   376→
   377→   377→> один seed + один список команд = одно состояние
   378→   378→
   379→   379→Но в engine/rules/workers используются `Date.now()` и `Math.random()`:
   380→   380→
   381→   381→- `src/engine/core/GameConfig.ts` — default seed через `Date.now()`;
   382→   382→- `src/engine/rules/cityRules.ts` — city id через `Date.now()` + `Math.random()`;
   383→   383→- `src/engine/rules/recruitmentRules.ts` — unit id через `Date.now()` + `Math.random()`;
   384→   384→- `src/engine/ai/AiDirector.ts` — mistake probability через `Math.random()`;
   385→   385→- `src/workers/simulation.worker.ts` — city/unit ids через `Date.now()` + `Math.random()`;
   386→   386→- `src/components/screens/NewGameScreen.tsx` — seed через `Date.now()`.
   387→   387→
   388→   388→UI/audio particles могут использовать `Math.random()` — это нормально, если не влияет на game state. Но engine/rules/simulation — нельзя.
   389→   389→
   390→   390→### 5.8. Worker protocol не содержит requestId
   391→   391→
   392→   392→Файлы:
   393→   393→
   394→   394→- `src/workers/workerProtocol.ts`
   395→   395→- `src/workers/workerManager.ts`
   396→   396→
   397→   397→`WorkerManager` создаёт `requestId`, но не отправляет его в worker message и не получает обратно в response. Ответы мапятся по типу и FIFO:
   398→   398→
   399→   399→```ts
   400→   400→for (const [requestId] of this.pendingRequests) {
   401→   401→  if (
   402→   402→    (responseType === 'findPathResult' && requestId.startsWith('pathfinding-')) ||
   403→   403→    ...
   404→   404→  ) {
   405→   405→    matchedId = requestId;
   406→   406→    break;
   407→   407→  }
   408→   408→}
   409→   409→```
   410→   410→
   411→   411→Это хрупко для конкурентных запросов одного типа. Правильно: request/response должны содержать `requestId`.
   412→   412→
   413→   413→### 5.9. Terrain chunk rendering реализован неполно
   414→   414→
   415→   415→Файл: `src/components/game3d/TerrainLayer.tsx`
   416→   416→
   417→   417→При больших картах строятся chunks:
   418→   418→
   419→   419→```tsx
   420→   420→{terrainChunks.length > 0 && (
   421→   421→  <ChunkedTerrain chunks={terrainChunks} />
   422→   422→)}
   423→   423→```
   424→   424→
   425→   425→Но затем всё равно рендерятся индивидуальные `HexMesh` для всех tiles:
   426→   426→
   427→   427→```tsx
   428→   428→{tiles.map((tile) => {
   429→   429→  return (
   430→   430→    <group key={key}>
   431→   431→      <HexMesh ... />
   432→   432→    </group>
   433→   433→  );
   434→   434→})}
   435→   435→```
   436→   436→
   437→   437→То есть оптимизация частично нивелирована.
   438→   438→
   439→   439→Плюс cleanup сделан через `useMemo`, а не `useEffect`:
   440→   440→
   441→   441→```tsx
   442→   442→useMemo(() => {
   443→   443→  return () => {
   444→   444→    if (terrainChunks.length > 0) {
   445→   445→      disposeChunks(terrainChunks);
   446→   446→    }
   447→   447→  };
   448→   448→}, [terrainChunks]);
   449→   449→```
   450→   450→
   451→   451→Возвращаемая функция из `useMemo` не является React cleanup. Это риск GPU/resource leaks.
   452→   452→
   453→   453→### 5.10. UI содержит placeholder-действия
   454→   454→
   455→   455→Файл: `src/components/hud/UnitPanel.tsx`

   466→   466→

   519→   519→## 7. Security review
   520→   520→
   521→   521→### 7.1. Критичные security-риски
   522→   522→
   523→   523→#### 7.1.1. SSRF/open proxy через Caddy
   524→   524→
   525→   525→**Файл:** `Caddyfile`
   526→   526→
   527→   527→Текущий код позволяет клиенту задать порт:
   528→   528→
   529→   529→```caddy
   530→   530→reverse_proxy localhost:{query.XTransformPort}
   531→   531→```
   532→   532→
   533→   533→**Сценарий атаки:**
   534→   534→
   535→   535→1. Атакующий отправляет запрос с `?XTransformPort=12345`.
   536→   536→2. Caddy проксирует на `localhost:12345`.
   537→   537→3. Если на localhost есть internal service/admin/debug endpoint, он может быть доступен извне через Caddy.
   538→   538→
   539→   539→**Что сделать:**
   540→   540→
   541→   541→```caddy
   542→   542→:81 {
   543→   543→  encode zstd gzip
   544→   544→
   545→   545→  header {
   546→   546→    X-Content-Type-Options "nosniff"
   547→   547→    X-Frame-Options "DENY"
   548→   548→    Referrer-Policy "strict-origin-when-cross-origin"
   549→   549→  }
   550→   550→
   551→   551→  reverse_proxy 127.0.0.1:3000 {
   552→   552→    header_up Host {host}
   553→   553→    header_up X-Forwarded-For {remote_host}
   554→   554→    header_up X-Forwarded-Proto {scheme}
   555→   555→    header_up X-Real-IP {remote_host}
   556→   556→  }
   557→   557→}
   558→   558→```
   559→   559→
   560→   560→Если нужен transform proxy для dev-инфраструктуры — вынести его в отдельный dev-only Caddyfile, не в production.
   561→   561→
   562→   562→#### 7.1.2. Save API без ownership
   563→   563→
   564→   564→**Файлы:**
   565→   565→
   566→   566→- `src/app/api/save/route.ts`
   567→   567→- `src/app/api/load/route.ts`
   568→   568→- `src/app/api/saves/route.ts`
   569→   569→- `prisma/schema.prisma`
   570→   570→
   571→   571→Текущая Prisma model:
   572→   572→
   573→   573→```prisma
   574→   574→model SaveGame {
   575→   575→  id        String   @id @default(cuid())
   576→   576→  name      String
   577→   577→  turn      Int
   578→   578→  players   String
   579→   579→  data      String
   580→   580→  checksum  String
   581→   581→  createdAt DateTime @default(now())
   582→   582→  updatedAt DateTime @updatedAt
   583→   583→}
   584→   584→```
   585→   585→
   586→   586→Нет владельца.
   587→   587→
   588→   588→**Минимальный production-вариант:**
   589→   589→
   590→   590→```prisma
   591→   591→model User {
   592→   592→  id        String     @id @default(cuid())
   593→   593→  email     String?    @unique
   594→   594→  name      String?
   595→   595→  saves     SaveGame[]
   596→   596→  createdAt DateTime   @default(now())
   597→   597→  updatedAt DateTime   @updatedAt
   598→   598→}
   599→   599→
   600→   600→model SaveGame {
   601→   601→  id        String   @id @default(cuid())
   602→   602→  ownerId   String
   603→   603→  owner     User     @relation(fields: [ownerId], references: [id], onDelete: Cascade)
   604→   604→  name      String
   605→   605→  turn      Int
   606→   606→  players   String
   607→   607→  data      String
   608→   608→  checksum  String
   609→   609→  version   Int      @default(1)
   610→   610→  createdAt DateTime @default(now())
   611→   611→  updatedAt DateTime @updatedAt
   612→   612→
   613→   613→  @@index([ownerId, updatedAt])
   614→   614→}
   615→   615→```
   616→   616→
   617→   617→Если проект должен быть strictly local single-player, то лучше вообще убрать server-side saves и хранить saves в IndexedDB/local file export. Но если приложение публичное и API остаются — нужен owner.
   618→   618→
   619→   619→#### 7.1.3. Нет body limit и schema validation
   620→   620→
   621→   621→Текущий endpoint:
   622→   622→
   623→   623→```ts
   624→   624→const body = await request.json();
   625→   625→const { name, turn, players, data, checksum } = body;
   626→   626→```
   627→   627→
   628→   628→Нужно:
   629→   629→
   630→   630→- ограничить body size;
   631→   631→- валидировать `name`, `turn`, `players`, `data`, `checksum`, `version`;
   632→   632→- reject unknown format;
   633→   633→- reject huge saves;
   634→   634→- reject malformed JSON;
   635→   635→- validate loaded save through engine save module.
   636→   636→
   637→   637→Пример направления:
   638→   638→
   639→   639→```ts
   640→   640→import { z } from 'zod';
   641→   641→
   642→   642→const MAX_SAVE_BYTES = 2_000_000;
   643→   643→
   644→   644→const SavePayloadSchema = z.object({
   645→   645→  name: z.string().trim().min(1).max(80),
   646→   646→  turn: z.number().int().min(0).max(100_000),
   647→   647→  players: z.string().max(500),
   648→   648→  data: z.string().min(2).max(MAX_SAVE_BYTES),
   649→   649→  checksum: z.string().regex(/^[a-f0-9]{8}$/i),
   650→   650→  version: z.number().int().min(1).max(100).optional(),
   651→   651→});
   652→   652→```
   653→   653→
   654→   654→Важно: FNV checksum не является security mechanism. Он годится для accidental corruption, но не для защиты от malicious tampering.
   655→   655→
   656→   656→### 7.2. Серьёзные security-риски
   657→   657→
   658→   658→#### 7.2.1. Prisma query logging всегда включён
   659→   659→
   660→   660→**Файл:** `src/lib/db.ts`
   661→   661→
   662→   662→```ts
   663→   663→new PrismaClient({
   664→   664→  log: ['query'],
   665→   665→})
   666→   666→```
   667→   667→
   668→   668→В production SQL-запросы и потенциально чувствительные данные могут попасть в логи. Исправить:
   669→   669→
   670→   670→```ts
   671→   671→new PrismaClient({
   672→   672→  log: process.env.NODE_ENV === 'development' ? ['query', 'warn', 'error'] : ['error'],
   673→   673→});
   674→   674→```
   675→   675→
   676→   676→#### 7.2.2. Next.js lock version требует security update
   677→   677→
   678→   678→В `bun.lock` фактически зафиксирован `next@16.1.3`. Для Next.js есть GitHub advisory `GHSA-q4gf-8mx6-v5v3`: affected range включает `>=16.0.0-beta.0 <16.2.3`, patched version — `16.2.3`.
   679→   679→
   680→   680→На практике лучше обновляться до актуальной patched 16.x-версии и прогонять полный regression test.
   681→   681→
   682→   682→Также в `package.json` указан `next-auth: ^4.24.11`, а в `bun.lock` фактически стоит `next-auth@4.24.13`. Advisory `GHSA-5jpx-9hw9-2fx4` затрагивает `<4.24.12`; lock уже выше, но manifest лучше поднять минимум до `^4.24.12` или актуального безопасного диапазона.
   683→   683→
   684→   684→#### 7.2.3. CSRF будущих mutation endpoints
   685→   685→
   686→   686→Сейчас auth нет. Если будет cookie-based auth, endpoints `POST /api/save` и `DELETE /api/load` должны иметь CSRF strategy:
   687→   687→
   688→   688→- SameSite cookies;
   689→   689→- CSRF token для mutating requests;
   690→   690→- Origin/Referer validation;
   691→   691→- server-side auth check внутри каждого handler.
   692→   692→

   719→   719→## 8. Архитектура: целевое состояние
   720→   720→
   721→   721→### 8.1. Текущая архитектура
   722→   722→
   723→   723→Текущая архитектура условно такая:
   724→   724→
   725→   725→```text
   726→   726→Next.js App Router
   727→   727→  ├─ UI screens / HUD
   728→   728→  ├─ Zustand store
   729→   729→  │   ├─ sessionSlice -> GameEngine
   730→   730→  │   ├─ commandSlice
   731→   731→  │   ├─ selectionSlice
   732→   732→  │   └─ settingsSlice
   733→   733→  ├─ GameEngine
   734→   734→  │   ├─ rules
   735→   735→  │   ├─ systems
   736→   736→  │   ├─ EventBus
   737→   737→  │   ├─ CommandQueue
   738→   738→  │   └─ GameRng
   739→   739→  ├─ rendering / React Three Fiber
   740→   740→  ├─ Web Workers
   741→   741→  └─ API routes + Prisma + SQLite
   742→   742→```
   743→   743→
   744→   744→Идея правильная, но есть нарушение слоёв:
   745→   745→
   746→   746→- UI/API сохраняют raw `GameState`, обходя `src/engine/save`;
   747→   747→- `sessionSlice.loadGame` приблизительно реконструирует `GameConfig`;
   748→   748→- worker simulation имеет simplified duplicate rules;
   749→   749→- AI может silent-skip invalid commands;
   750→   750→- UI знает детали API сохранений напрямую.
   751→   751→
   752→   752→### 8.2. Целевая архитектура save/load
   753→   753→
   754→   754→Нужно сделать единый путь:
   755→   755→
   756→   756→```text
   757→   757→UI
   758→   758→  ↓
   759→   759→SaveClient / store action
   760→   760→  ↓
   761→   761→SaveService
   762→   762→  ├─ engine.saveGame(...)
   763→   763→  ├─ serializeSave(...)
   764→   764→  ├─ calculateChecksum(...)
   765→   765→  ├─ validate size/schema
   766→   766→  ↓
   767→   767→/api/save
   768→   768→  ├─ auth/owner check
   769→   769→  ├─ zod validation
   770→   770→  ├─ DB write
   771→   771→  ↓
   772→   772→Prisma SaveGame
   773→   773→```
   774→   774→
   775→   775→Load:
   776→   776→
   777→   777→```text
   778→   778→/api/load
   779→   779→  ├─ auth/owner check
   780→   780→  ├─ DB read
   781→   781→  ↓
   782→   782→SaveService
   783→   783→  ├─ deserializeSave(...)
   784→   784→  ├─ validateSave(...)
   785→   785→  ├─ applyMigrations(...)
   786→   786→  ├─ verify checksum
   787→   787→  ↓
   788→   788→sessionSlice.loadSaveFile(saveFile)
   789→   789→  ├─ new GameEngine(saveFile.gameConfig)
   790→   790→  ├─ engine.setState(saveFile.gameState)
   791→   791→  ├─ rng.setState(saveFile.rngState.position/state)
   792→   792→  ├─ restore commandLog if supported
   793→   793→```
   794→   794→
   795→   795→### 8.3. Целевая архитектура determinism
   796→   796→
   797→   797→Запретить в `src/engine`, `src/workers/simulation.worker.ts`, `src/engine/rules`:
   798→   798→
   799→   799→- `Math.random()`;
   800→   800→- `Date.now()` для game-state decisions;
   801→   801→- random ID generation without seeded RNG/counter.
   802→   802→
   803→   803→Добавить в `GameState`:
   804→   804→
   805→   805→```ts
   806→   806→nextEntitySeq: number;
   807→   807→nextCitySeq: number;
   808→   808→rngState: number;
   809→   809→```
   810→   810→
   811→   811→Или отдельный `IdGenerator`:
   812→   812→
   813→   813→```ts
   814→   814→function nextCityId(state: GameState): { state: GameState; id: CityId } {
   815→   815→  const seq = state.nextCitySeq ?? 1;
   816→   816→  return {
   817→   817→    state: { ...state, nextCitySeq: seq + 1 },
   818→   818→    id: `city-${seq}`,
   819→   819→  };
   820→   820→}
   821→   821→```
   822→   822→
   823→   823→Для random:
   824→   824→
   825→   825→- engine owns `GameRng`;
   826→   826→- systems/rules получают RNG или random decisions как аргумент;
   827→   827→- save stores rng internal state;
   828→   828→- load restores rng state.
