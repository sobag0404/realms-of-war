    40→## 1. Краткий вердикт
    41→
    42→`Realms of War` — амбициозный alpha-прототип fantasy 4X/TBS-игры на **Next.js + TypeScript + React Three Fiber + Zustand + Prisma/SQLite**.
    43→
    44→Проект выглядит значительно серьёзнее обычного учебного CRUD: есть игровой engine, hex-математика, ECS-подход, command pattern, EventBus, mapgen, AI, workers, 3D-рендеринг, HUD, save/load, GDD и project context.
    45→
    46→Но по engineering discipline проект пока не production-ready. Основные блокеры:
    47→
    48→- публичные save/load/delete API без авторизации и ownership;
    49→- опасный Caddy reverse proxy через query-параметр `XTransformPort`;
    50→- `next.config.ts` игнорирует TypeScript build errors;
    51→- ESLint фактически обезврежен;
    52→- реальных тестов нет;
    53→- save/load в UI/API обходит engine-level save-модуль;
    54→- детерминизм заявлен в архитектуре, но нарушен через `Math.random()` и `Date.now()` в engine/rules/workers;
    55→- есть placeholders в пользовательских действиях;
    56→- нет полноценного root `README.md`, `.env.example`, CI/CD и production-инструкции.
    57→
    58→**Текущий уровень:** сильный WIP/alpha-прототип, ближе к `junior+ / middle-` по зрелости реализации. Архитектурная задумка местами тянет на `middle/middle+`, но безопасность, тесты, build discipline и deploy-подход ниже production-уровня.

   223→## 5. Главные слабые места
   224→
   225→### 5.1. TypeScript build errors игнорируются
   226→
   227→Файл: `next.config.ts`
   228→
   229→```ts
   230→const nextConfig: NextConfig = {
   231→  output: "standalone",
   232→  typescript: {
   233→    ignoreBuildErrors: true,
   234→  },
   235→  reactStrictMode: false,
   236→  allowedDevOrigins: ["21.0.15.156"],
   237→};
   238→```
   239→
   240→Проблема:
   241→
   242→- production build может проходить со сломанной типизацией;
   243→- реальные ошибки маскируются;
   244→- AI-разработчик может добавлять несовместимый код, а проект всё равно “соберётся”.
   245→
   246→Найден пример, который likely должен ловиться типизацией:
   247→
   248→Файл: `src/components/providers/GameProvider.tsx`
   249→
   250→```ts
   251→const unsubKilled = eventBus.on('event') as () => void; // placeholder
   252→```
   253→
   254→`'event'` не входит в `GameEventType`. Это placeholder, замаскированный отключёнными проверками.

   309→Файл: `src/store/slices/sessionSlice.ts`

   331→### 5.5. Публичные API сохранений небезопасны
   332→
   333→Файлы:
   334→
   335→- `src/app/api/save/route.ts`
   336→- `src/app/api/load/route.ts`
   337→- `src/app/api/saves/route.ts`
   338→
   339→Проблемы:
   340→
   341→- нет auth;
   342→- нет owner/user/session ID;
   343→- нет проверки владельца сохранения;

   351→
   352→### 5.6. Caddyfile содержит SSRF/open proxy риск
   353→
   354→Файл: `Caddyfile`
   355→
   356→```caddy
   357→@transform_port_query {
   358→  query XTransformPort=*
   359→}
   360→
   361→handle @transform_port_query {
   362→  reverse_proxy localhost:{query.XTransformPort} {
   363→    header_up Host {host}
   364→    header_up X-Forwarded-For {remote_host}
   365→    header_up X-Forwarded-Proto {scheme}
   366→    header_up X-Real-IP {remote_host}
   367→  }
   368→}
   369→```
   370→
   371→Проблема: пользовательский query-параметр управляет локальным портом reverse proxy. Это потенциальный SSRF/open local proxy.
   372→
   373→### 5.7. Детерминизм нарушен
   374→
   375→Архитектурная цель из `PROJECT_CONTEXT.md`:
   376→
   377→> один seed + один список команд = одно состояние
   378→
   379→Но в engine/rules/workers используются `Date.now()` и `Math.random()`:
   380→
   381→- `src/engine/core/GameConfig.ts` — default seed через `Date.now()`;
   382→- `src/engine/rules/cityRules.ts` — city id через `Date.now()` + `Math.random()`;
   383→- `src/engine/rules/recruitmentRules.ts` — unit id через `Date.now()` + `Math.random()`;
   384→- `src/engine/ai/AiDirector.ts` — mistake probability через `Math.random()`;
   385→- `src/workers/simulation.worker.ts` — city/unit ids через `Date.now()` + `Math.random()`;
   386→- `src/components/screens/NewGameScreen.tsx` — seed через `Date.now()`.
   387→
   388→UI/audio particles могут использовать `Math.random()` — это нормально, если не влияет на game state. Но engine/rules/simulation — нельзя.
   389→
   390→### 5.8. Worker protocol не содержит requestId
   391→
   392→Файлы:
   393→
   394→- `src/workers/workerProtocol.ts`
   395→- `src/workers/workerManager.ts`
   396→
   397→`WorkerManager` создаёт `requestId`, но не отправляет его в worker message и не получает обратно в response. Ответы мапятся по типу и FIFO:
   398→
   399→```ts
   400→for (const [requestId] of this.pendingRequests) {
   401→  if (
   402→    (responseType === 'findPathResult' && requestId.startsWith('pathfinding-')) ||
   403→    ...
   404→  ) {
   405→    matchedId = requestId;
   406→    break;
   407→  }
   408→}
   409→```
   410→
   411→Это хрупко для конкурентных запросов одного типа. Правильно: request/response должны содержать `requestId`.
   412→
   413→### 5.9. Terrain chunk rendering реализован неполно
   414→
   415→Файл: `src/components/game3d/TerrainLayer.tsx`
   416→
   417→При больших картах строятся chunks:
   418→
   419→```tsx
   420→{terrainChunks.length > 0 && (
   421→  <ChunkedTerrain chunks={terrainChunks} />
   422→)}
   423→```
   424→
   425→Но затем всё равно рендерятся индивидуальные `HexMesh` для всех tiles:
   426→
   427→```tsx
   428→{tiles.map((tile) => {
   429→  return (
   430→    <group key={key}>
   431→      <HexMesh ... />
   432→    </group>
   433→  );
   434→})}
   435→```
   436→
   437→То есть оптимизация частично нивелирована.
   438→
   439→Плюс cleanup сделан через `useMemo`, а не `useEffect`:
   440→
   441→```tsx
   442→useMemo(() => {
   443→  return () => {
   444→    if (terrainChunks.length > 0) {
   445→      disposeChunks(terrainChunks);
   446→    }
   447→  };
   448→}, [terrainChunks]);
   449→```
   450→
   451→Возвращаемая функция из `useMemo` не является React cleanup. Это риск GPU/resource leaks.
   452→
   453→### 5.10. UI содержит placeholder-действия

   497→## 6. Критичные проблемы P0/P1/P2
   498→
   499→| Приоритет | Проблема | Файлы | Почему опасно | Как исправить |
   500→|---|---|---|---|---|
   501→| P0 | User-controlled Caddy reverse proxy | `Caddyfile` | SSRF/open proxy на localhost-порты | Удалить `XTransformPort` handler. Оставить фиксированный `reverse_proxy 127.0.0.1:3000`. |
   502→| P0 | Save/load/delete API без auth/ownership | `src/app/api/*` | Любой может прочитать/удалить/создать saves | Добавить auth/session/ownerId или сделать saves strictly local-only. |

   519→## 7. Security review
   520→
   521→### 7.1. Критичные security-риски
   522→
   523→#### 7.1.1. SSRF/open proxy через Caddy
   524→
   525→**Файл:** `Caddyfile`
   526→
   527→Текущий код позволяет клиенту задать порт:
   528→
   529→```caddy
   530→reverse_proxy localhost:{query.XTransformPort}
   531→```
   532→
   533→**Сценарий атаки:**
   534→
   535→1. Атакующий отправляет запрос с `?XTransformPort=12345`.
   536→2. Caddy проксирует на `localhost:12345`.
   537→3. Если на localhost есть internal service/admin/debug endpoint, он может быть доступен извне через Caddy.
   538→
   539→**Что сделать:**
   540→
   541→```caddy
   542→:81 {
   543→  encode zstd gzip
   544→
   545→  header {
   546→    X-Content-Type-Options "nosniff"
   547→    X-Frame-Options "DENY"
   548→    Referrer-Policy "strict-origin-when-cross-origin"
   549→  }
   550→
   551→  reverse_proxy 127.0.0.1:3000 {
   552→    header_up Host {host}
   553→    header_up X-Forwarded-For {remote_host}
   554→    header_up X-Forwarded-Proto {scheme}
   555→    header_up X-Real-IP {remote_host}
   556→  }
   557→}
   558→```
   559→
   560→Если нужен transform proxy для dev-инфраструктуры — вынести его в отдельный dev-only Caddyfile, не в production.
   561→
   562→#### 7.1.2. Save API без ownership
   563→
   564→**Файлы:**
   565→
   566→- `src/app/api/save/route.ts`
   567→- `src/app/api/load/route.ts`
   568→- `src/app/api/saves/route.ts`
   569→- `prisma/schema.prisma`
   570→
   571→Текущая Prisma model:
   572→
   573→```prisma
   574→model SaveGame {
   575→  id        String   @id @default(cuid())
   576→  name      String
   577→  turn      Int
   578→  players   String
   579→  data      String
   580→  checksum  String
   581→  createdAt DateTime @default(now())
   582→  updatedAt DateTime @updatedAt
   583→}
   584→```
   585→
   586→Нет владельца.
   587→
   588→**Минимальный production-вариант:**
   589→
   590→```prisma
   591→model User {
   592→  id        String     @id @default(cuid())
   593→  email     String?    @unique
   594→  name      String?
   595→  saves     SaveGame[]
   596→  createdAt DateTime   @default(now())
   597→  updatedAt DateTime   @updatedAt
   598→}
   599→
   600→model SaveGame {
   601→  id        String   @id @default(cuid())
   602→  ownerId   String
   603→  owner     User     @relation(fields: [ownerId], references: [id], onDelete: Cascade)
   604→  name      String
   605→  turn      Int
   606→  players   String
   607→  data      String
   608→  checksum  String
   609→  version   Int      @default(1)
   610→  createdAt DateTime @default(now())
   611→  updatedAt DateTime @updatedAt
   612→
   613→  @@index([ownerId, updatedAt])
   614→}
   615→```
   616→
   617→Если проект должен быть strictly local single-player, то лучше вообще убрать server-side saves и хранить saves в IndexedDB/local file export. Но если приложение публичное и API остаются — нужен owner.
   618→
   619→#### 7.1.3. Нет body limit и schema validation
   620→
   621→Текущий endpoint:
   622→
   623→```ts
   624→const body = await request.json();
   625→const { name, turn, players, data, checksum } = body;
   626→```
   627→
   628→Нужно:
   629→
   630→- ограничить body size;
   631→- валидировать `name`, `turn`, `players`, `data`, `checksum`, `version`;
   632→- reject unknown format;
   633→- reject huge saves;
   634→- reject malformed JSON;
   635→- validate loaded save through engine save module.
   636→
   637→Пример направления:
   638→
   639→```ts
   640→import { z } from 'zod';
   641→
   642→const MAX_SAVE_BYTES = 2_000_000;
   643→
   644→const SavePayloadSchema = z.object({
   645→  name: z.string().trim().min(1).max(80),
   646→  turn: z.number().int().min(0).max(100_000),
   647→  players: z.string().max(500),
   648→  data: z.string().min(2).max(MAX_SAVE_BYTES),
   649→  checksum: z.string().regex(/^[a-f0-9]{8}$/i),
   650→  version: z.number().int().min(1).max(100).optional(),
   651→});
   652→```
   653→
   654→Важно: FNV checksum не является security mechanism. Он годится для accidental corruption, но не для защиты от malicious tampering.
   655→

   719→## 8. Архитектура: целевое состояние
   720→
   721→### 8.1. Текущая архитектура
   722→
   723→Текущая архитектура условно такая:
   724→
   725→```text
   726→Next.js App Router
   727→  ├─ UI screens / HUD
   728→  ├─ Zustand store
   729→  │   ├─ sessionSlice -> GameEngine
   730→  │   ├─ commandSlice
   731→  │   ├─ selectionSlice
   732→  │   └─ settingsSlice
   733→  ├─ GameEngine
   734→  │   ├─ rules
   735→  │   ├─ systems
   736→  │   ├─ EventBus
   737→  │   ├─ CommandQueue
   738→  │   └─ GameRng
   739→  ├─ rendering / React Three Fiber
   740→  ├─ Web Workers
   741→  └─ API routes + Prisma + SQLite
   742→```
   743→
   744→Идея правильная, но есть нарушение слоёв:
   745→
   746→- UI/API сохраняют raw `GameState`, обходя `src/engine/save`;
   747→- `sessionSlice.loadGame` приблизительно реконструирует `GameConfig`;
   748→- worker simulation имеет simplified duplicate rules;
   749→- AI может silent-skip invalid commands;
   750→- UI знает детали API сохранений напрямую.
   751→
   752→### 8.2. Целевая архитектура save/load
   753→
   754→Нужно сделать единый путь:
   755→
   756→```text
   757→UI
   758→  ↓
   759→SaveClient / store action
   760→  ↓
   761→SaveService
   762→  ├─ engine.saveGame(...)
   763→  ├─ serializeSave(...)
   764→  ├─ calculateChecksum(...)
   765→  ├─ validate size/schema
   766→  ↓
   767→/api/save
   768→  ├─ auth/owner check
   769→  ├─ zod validation
   770→  ├─ DB write
   771→  ↓
   772→Prisma SaveGame
   773→```
   774→
   775→Load:
   776→
   777→```text
   778→/api/load
   779→  ├─ auth/owner check
   780→  ├─ DB read
   781→  ↓
   782→SaveService
   783→  ├─ deserializeSave(...)
   784→  ├─ validateSave(...)
   785→  ├─ applyMigrations(...)
   786→  ├─ verify checksum
   787→  ↓
   788→sessionSlice.loadSaveFile(saveFile)
   789→  ├─ new GameEngine(saveFile.gameConfig)
   790→  ├─ engine.setState(saveFile.gameState)
   791→  ├─ rng.setState(saveFile.rngState.position/state)
   792→  ├─ restore commandLog if supported
   793→```
   794→
   795→### 8.3. Целевая архитектура determinism
   796→
   797→Запретить в `src/engine`, `src/workers/simulation.worker.ts`, `src/engine/rules`:
   798→
   799→- `Math.random()`;
   800→- `Date.now()` для game-state decisions;
   801→- random ID generation without seeded RNG/counter.
   802→
   803→Добавить в `GameState`:
   804→
   805→```ts
   806→nextEntitySeq: number;
   807→nextCitySeq: number;
   808→rngState: number;
   809→```
   810→
   811→Или отдельный `IdGenerator`:
   812→
   813→```ts
   814→function nextCityId(state: GameState): { state: GameState; id: CityId } {
   815→  const seq = state.nextCitySeq ?? 1;
   816→  return {
   817→    state: { ...state, nextCitySeq: seq + 1 },
   818→    id: `city-${seq}`,
   819→  };
   820→}
   821→```
   822→
   823→Для random:
   824→
   825→- engine owns `GameRng`;
   826→- systems/rules получают RNG или random decisions как аргумент;
   827→- save stores rng internal state;
   828→- load restores rng state.
